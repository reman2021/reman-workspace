# 迁移与兼容

## 名称与安装目录

当前仓库名、包名和插件 ID 均为 `reman-workspace`，显示名称为 Reman Workspace。项目源自 [PandoraReads/apex-dashboard](https://github.com/PandoraReads/apex-dashboard)，继续保留上游署名和 MIT 许可。

新安装目录应为：

```text
<Vault>/.obsidian/plugins/reman-workspace/
```

代码仓库或本地检出目录改名不会改变 Vault 内的旧视图、状态键和主页 Markdown。迁移时不要先删除旧 `.obsidian/plugins/apex-dashboard/`：旧设置导入和历史备份都依赖其中的文件。先禁用旧插件，安装并验证 Reman Workspace，再决定是否归档旧目录。

## 视图与本地状态

当前视图类型是 `reman-workspace-view`，同时继续注册 `apex-dashboard-view`，使既有 Obsidian 工作区布局可被加载。打开主页后使用当前视图类型；无需手工编辑工作区布局文件。

以下旧状态键继续作为读取回退，后续操作写入新的 `reman-workspace-*` 键：

| 状态 | 当前键 | 兼容读取的旧键 |
| --- | --- | --- |
| 分区折叠 | `reman-workspace-collapsed` | `apex-dashboard-collapsed` |
| 显示归档 | `reman-workspace-show-archived` | `apex-dashboard-show-archived` |
| 侧栏固定 | `reman-workspace-sidebar-pinned` | `apex-dashboard-sidebar-pinned`，以及早期 `sidebar-pinned` |
| 横幅折叠 | `reman-workspace-banner-collapsed` | `apex-dashboard-banner-collapsed`，以及早期 `banner-collapsed` |

主页根节点同时保留 `reman-workspace-root` 和 `apex-dashboard-root` 类，供当前样式和旧选择器兼容使用。

## 设置导入

插件先读取当前 `reman-workspace` 的设置。仅当当前设置不存在或为空时，才尝试读取：

```text
<Vault>/.obsidian/plugins/apex-dashboard/data.json
```

读取成功后，合并默认值并保存为当前插件设置。此后修改只写当前设置，不会与旧 `data.json` 双向同步。若当前设置已经存在，则不会用旧设置覆盖。

旧 `stylePreset` 字段仍可反序列化，但运行时始终归一为 `default`；项目不再根据旧值切换外观，无需手工删除该字段。

## 主页 Markdown

迁移时应继续使用原主页文件，并在设置中填写其 Vault 相对路径。不要用[最小主页示例](../examples/dashboard-template.md)覆盖现有内容。

- 旧 `type: notes` 分区读取时归一为统一的 `projects`／笔记分区；下一次主页序列化时类型会按当前格式写回。
- 旧 `type: weather` 卡片不再渲染。解析器把该卡片的原始 Markdown 作为不透明块保存，编辑其他卡片时仍按原内容写回。
- 旧天气、农历等笔记属性和历史记录文件不会被自动删除，也不要求全库迁移。
- Todo 来源配置保存在主页 frontmatter，但任务正文仍在来源文件中。勾选来源任务直接修改来源文件，不属于主页 Markdown 写入或备份。

## 备份

当前 `SyncEngine` 在改写主页前把原内容备份到：

```text
<Vault>/.obsidian/plugins/reman-workspace/backups/
```

文件名为 UTC 时间戳形式的 `dashboard-*.md`，按文件名排序后最多保留 5 份。备份创建失败不会阻止主页写入。

旧目录 `.obsidian/plugins/apex-dashboard/backups/` 不会自动搬运，也不会由当前保留策略清理。需要继续保留时，请维持旧目录或手工复制所需文件；复制前后都不要把历史备份误认为当前主页。Todo 来源文件不在上述主页备份范围内。

## 建议迁移步骤

1. 备份 Vault 的主页 Markdown、`.obsidian/plugins/apex-dashboard/data.json` 和旧 `backups/`。
2. 禁用旧插件，但暂时保留旧插件目录。
3. 将当前根目录的 `main.js`、`styles.css`、`manifest.json` 放入 `.obsidian/plugins/reman-workspace/`。
4. 重新加载 Obsidian，启用 Reman Workspace，并确认 Dashboard 文件仍指向原主页。
5. 核对旧工作区入口、分区折叠、归档显示、横幅、笔记分区和隐藏天气块均符合预期。
6. 编辑一个普通主页卡片并检查当前备份目录；另行测试 Todo 来源卡回写及来源文件恢复方案。
7. 确认设置已导入且不再需要回退后，再归档或删除旧插件代码；旧备份是否保留由用户决定。
