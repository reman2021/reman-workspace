# 架构说明

## 定位与边界

Reman Workspace 是 Obsidian 插件，插件 ID 为 `reman-workspace`。主页 Markdown 是主要持久化数据源；插件设置保存在 Obsidian 插件数据中，界面折叠等轻量状态保存在本地状态键中。项目保留对旧 `apex-dashboard` 标识和既有主页内容的读取兼容。

源码按运行层、数据层和功能领域组织：

| 目录或入口 | 职责 |
| --- | --- |
| `src/main.ts` | 插件启动、设置加载、视图注册、命令与设置页注册 |
| `src/app/` | 应用层。`dashboard-view.ts` 管理视图生命周期、局部刷新和资源清理，`dashboard-renderer.ts` 编排页面与分区，`sidebar-calendar.ts` 渲染侧栏周历，`settings.ts` 提供设置页 |
| `src/core/` | 稳定内部契约。`types.ts` 定义数据与更新范围，`identity.ts` 集中当前及旧身份，`i18n/index.ts` 提供翻译入口并加载 `en.ts`、`zh.ts` 词典 |
| `src/data/markdown/` | `parse.ts`、`serialize.ts`、`default.ts` 分别负责解析、序列化和默认主页，`index.ts` 是统一入口；兼容归一化在解析链路完成 |
| `src/data/sync/` | `sync-engine.ts` 协调数据更新、通知和串行写入，`backup-store.ts` 管理主页备份，`utils.ts` 提供写入哈希与日期工具 |
| `src/features/` | 按横幅、卡片、数据库、快捷操作、最近文件、Todo 来源、追踪和模板划分用户功能 |
| `src/ui/` | 弹窗初始化、主题变量继承、确认框、文件搜索／建议、富文本链接和 CSS 颜色解析等共享界面能力 |
| `src/utils/` | 异步回调、Obsidian 内部命令访问和值转换等无界面工具 |
| `src/styles/` | 按固定顺序维护令牌、页面、横幅侧栏、分区卡片、弹窗、Todo／追踪、数据库和响应式覆盖；构建后生成根目录 `styles.css` |

卡片渲染继续按领域拆分：`features/cards/task-renderer.ts` 与 `memo-renderer.ts` 负责任务和 Memo，`reminder-popup.ts` 负责提醒日期门户，`reminder-controller.ts` 负责到期检查；`features/tracking/render.ts` 管理追踪图表。数据库的查询、日期门户、分区渲染与配置分别位于 `features/library/query.ts`、`calendar-popup.ts`、`section.ts` 和 `config-modal.ts`。

## 启动与视图

`DashboardPlugin.onload()` 先加载设置，再同时注册 `reman-workspace-view` 和旧 `apex-dashboard-view`。随后注册侧栏按钮、`open-dashboard` 命令和设置页；布局就绪后可按设置自动打开主页，Obsidian CSS 变化时刷新现有视图。

打开主页时优先复用已存在的新旧视图叶片，并把活动视图设为当前类型。`DashboardView.onOpen()` 创建并初始化 `SyncEngine`，订阅数据更新，注册 Vault 监听和提醒检查；`onClose()` 负责卸载来源控制器、图表、定时器、DOM 监听和同步监听。

`DashboardView` 组合横幅、侧栏和主页分区。完整重绘先在离屏根节点构建内容，再一次替换可见根节点，同时保留必要的滚动位置，并尽量复用配置未变化的 `TodoSourceController`；可定位到单一范围的更新则走局部渲染，避免重建整个主页。

## Markdown 与同步主链路

主页文件路径来自设置中的 `dashboardFile`，未带 `.md` 时由 `SyncEngine` 补齐。文件不存在时会生成默认主页；仓库提供的[最小示例](../examples/dashboard-template.md)可用于理解格式，但不应覆盖已有主页。

主页 Markdown 的 frontmatter 保存横幅、快捷操作、分区定义、Todo 来源配置、数据库及热力图配置；正文按二级标题组织分区，三级标题及其元数据、任务或正文表示卡片。`data/markdown` 的 `parse()` 生成 `DashboardData`，`serialize()` 再写回 Markdown。

主数据流为：

1. `SyncEngine.init()` 定位或创建主页，注册文件监听并解析初始内容。
2. `DashboardView` 根据 `DashboardUpdate` 完整或局部渲染。
3. 普通卡片操作经视图回调调用 `SyncEngine` 的更新方法。
4. `SyncEngine` 序列化数据，先在当前插件目录创建主页备份，再通过写入队列修改主页。
5. 主页被外部修改时，监听器防抖后重新解析，并发送完整更新。

写入前若新内容小于当前文件的 30%，同步会跳过该次写入，避免异常截断。备份失败不会阻断主页写入；备份目录和恢复边界见[迁移与兼容](迁移与兼容.md)。

## `DashboardUpdate` 契约

`src/core/types.ts` 中的 `DashboardUpdate` 描述渲染影响范围：

| `scope` | 处理方式 |
| --- | --- |
| `full` | 按 `initial`、`external`、`settings`、`structure` 或 `mixed` 原因完整重绘 |
| `columns` | 只重绘给定 `columnNames` 对应的分区 |
| `quick-actions` | 只更新快捷操作区域 |
| `banner` | 只更新横幅 |

新增写操作时，应返回能覆盖其真实影响的最小范围；涉及分区结构、无法定位卡片所属分区或混合变化时使用完整更新。

## Todo 来源旁路

Todo 分区的 `todoSources` 配置保存在主页 frontmatter，但来源任务不会序列化进主页。每个启用来源的 Todo 分区由 `features/todo-source/controller.ts` 中的 `TodoSourceController` 管理：它按本地日期解析路径模板，从来源文件读取复选框任务，并监听来源文件创建、修改、删除、重命名、窗口聚焦和跨日变化。

用户勾选来源任务时，控制器通过 `Vault.process()` 直接修改来源文件中的一个复选框字符。若外部修改后无法唯一定位原任务，写入会拒绝并提示，不猜测目标。这个旁路不经过 `SyncEngine`，因此不会触发主页 Markdown 备份；来源文件的恢复依赖 Vault 自身的版本记录或单独备份。

## 主题门户

主页根节点同时带有 `reman-workspace-root` 和旧 `apex-dashboard-root` 类，当前运行时使用单一 `default` 主题数据标记。大部分样式变量定义在该根节点范围内。

Obsidian 弹窗挂载在主页根节点之外，不能自然继承这些变量。`src/ui/theme.ts` 的 `initializeDashboardModal()` 通过 `findDashboardRoot()` 找到当前或旧根节点，把主题标记和必要的 `--db-*` 计算值复制到实际 `modalEl`，并将单层外框样式应用到 Obsidian 的弹窗表面。提醒和数据库日期门户同样调用主题变量继承方法。新增门户式 UI 时也应显式传递主题变量，而不是假设它位于主页 DOM 子树中。

## 兼容层

兼容标识集中在 `src/core/identity.ts`。当前代码继续注册旧视图类型、读取旧本地状态键，并在当前设置不存在时从旧插件目录导入设置。解析器把旧 `type: notes` 归一为统一笔记分区，并将旧天气卡片作为不渲染的原始 Markdown 块保留。详细迁移步骤与不可自动搬运的内容见[迁移与兼容](迁移与兼容.md)。
